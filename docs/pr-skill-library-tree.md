# 修复 Skill 识别：按名称分组，点击查看文件树

Base: `feature/skills-mcp-only`，依赖 PR #3。

## 用户可见的变化

- 一个 Skill 在主列表里只显示一项，不再把 SKILL.md、脚本、参考文档逐一列成独立 Skill。
- 点击 Skill 显示目录文件树，文件夹可展开 / 折叠；默认查看 SKILL.md，点击子文件查看内容或本机 / 对端差异。
- 名称优先取入口文件的简单单行 `name`，其次一级标题，最后目录名。复杂 YAML 使用回退规则，没有引入 YAML package。
- 搜索内部文件名仍显示所属整个 Skill，文件树不会因搜索而截断。
- 勾选以 Skill 为单位，一起选择它所有新增或不同的可共享文件，相同文件不重复写入。本机独有文件仍不删除。
- 数量按 Skill / MCP 服务组展示，确认时另外说明实际文件数。MCP 合并与隐私限制不变。

## 识别规则

- 用 SKILL.md 所在目录识别 Skill，支持文件名大小写不敏感匹配。
- 嵌套 Skill 归属最近的入口目录，父 Skill 不包含子 Skill 的文件。
- 不同 Agent / 路径下的同名 Skill 不合并。
- 散落文件和没有安全可共享入口的目录不作为 Skill 共享。
- 文件树只显示通过原有安全过滤的文本文件，被排除的文件仍在排除提示中说明。不是未经筛选的完整目录复制，也不是跨文件事务。

## 技术说明

- 纯 TypeScript 分组 / 目录树模型同时用于扫描、渲染和测试，无新增 package。
- 浏览器模块单独输出到 dist/browser，与主进程 CommonJS 输出隔离；sandbox、CSP、定向 IPC 保持不变。
- 现有 v2 文件级同步协议保持兼容，仅 UI 按 Skill 展示和选择。

- `npm run test:smoke`：真实 GUI 验证一个三文件 Skill 只显示一项，展开 / 折叠目录，点击脚本预览；搜索子文件名后按 Skill 选择，确认并拉取所有变化文件，保留相同资源文件。

## 手动验收

1. 用至少包含 SKILL.md、scripts/ 和 references/ 的 Skill 启动应用。
2. 主列表只应显示一个 Skill；点击后在右侧看文件树，点任意文件查看内容。
3. 搜索 scripts 内的文件名，仍应返回 Skill 名称及完整可共享文件树。
4. 对端预览后勾选 Skill，确认显示 Skill 数和实际文件数，拉取后检查各变化文件均更新。
